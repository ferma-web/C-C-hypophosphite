# Catalysis Screen — восстановленные соединения

Сайт с карточками веществ проекта «Hypophosphite C=C Reduction» (OdanLab).
Живая версия: https://ferma-web.github.io/C-C-hypophosphite/

## Что умеет сайт

- **Редактировать может любой, у кого есть ссылка.** Наведите курсор на карточку → появится кнопка ✎ → правите любые поля и структуру → «Сохранить». Изменения сразу видны всем (другие открытые вкладки обновляются сами).
- **Новая карточка** (кнопка вверху):
  - **по шифру** — вводите шифр реакции (`AAP-36`, `kir 46` — регистр и дефис не важны, есть автодополнение) → название, выходы, загрузка, формула, CAS и структура подтягиваются из OdanLab; если карточка с таким шифром уже есть, сайт предупредит;
  - **вручную** — рисуете молекулу во встроенном редакторе Ketcher (или вставляете SMILES), вписываете выход и название; формула считается из структуры автоматически.
- **Перетаскивание**: потяните карточку мышью в другой раздел — категория сменится; в режиме «по классам» перенос в другой столбец меняет и класс.
- **Классы веществ** (нитростиролы, цианоэфиры, …): задаются в карточке (выбрать из существующих или вписать новый). Кнопка «По классам» у каждого раздела раскладывает его карточки по столбцам, кнопка в шапке — сразу все разделы.
- **Удаление «мягкое»**: удалённые карточки лежат внизу страницы в разделе «Удалённые карточки», их можно восстановить. Кроме того, база хранит журнал всех правок (`molecule_history`).
- Если двое правят одну карточку одновременно, второй получит предупреждение и сможет выбрать — перезаписать или открыть свежую версию.
- Поле «Кто правит» запоминается в браузере и попадает в историю изменений.

## Откуда берутся данные

```
OdanLab ──(Claude + коннектор OdanLab, раз в день)──▶ Supabase: odanlab_reactions (справочник по шифрам)
                                                            │ триггер: новые выходы → в карточки
сайт (браузер) ◀────────────── читает/пишет ─────────▶ Supabase: molecules (карточки)
                                                            │
GitHub Action (каждые ~10 мин) ◀────────── читает ─────────┘
        └──▶ коммит в data/*.json (архив + история правок в git)
```

- **Supabase** — «живая» база. Таблицы и политики доступа описаны в [`supabase/schema.sql`](supabase/schema.sql):
  - `molecules` — карточки сайта;
  - `molecule_history` — старая версия строки при каждом изменении (для отката);
  - `odanlab_reactions` — все реакции проекта OdanLab (шифр, продукт, выходы, SMILES). На сайте отдельно не показываются — только когда создаёте карточку по шифру.
- **Обновление из OdanLab** делает ежедневная задача Claude с коннектором OdanLab: выгружает реакции проекта, `scripts/odanlab_sync.py` превращает их в SQL (только новые/изменённые реакции, molfile → SMILES через `scripts/molsmi.py`), и Claude записывает это в Supabase. Если у реакции поменялся выход, триггер в базе обновит карточки с этим шифром — **но только те поля, которые никто не правил на сайте руками**.
- **Архив в GitHub** — [`.github/workflows/archive.yml`](.github/workflows/archive.yml) каждые ~10 минут запускает `scripts/export_from_supabase.py` и коммитит `data/molecules.json`, `data/molecules_deleted.json`, `data/odanlab_reactions.json`, если что-то изменилось. Если Supabase вдруг недоступен, сайт показывает эту архивную копию (только чтение).

## Деплой

`.github/workflows/pages.yml` при каждом пуше в `main` публикует сайт на GitHub Pages и **сам подкладывает Ketcher** (скачивает standalone-сборку из релизов `epam/ketcher` в папку `ketcher/`). В репозитории Ketcher не хранится. Версию можно закрепить переменной `KETCHER_VERSION` в этом файле.

Структуры на карточках рисуются в браузере через [RDKit.js](https://www.rdkit.org/docs/JavaScriptWrapper.html) (грузится с unpkg). У старых карточек остались готовые картинки в `assets/structures/` — при изменении структуры в редакторе картинка заменяется отрисовкой по SMILES.

## Доступ и безопасность

Сайт «по ссылке»: robots.txt и `noindex` не дают поисковикам его индексировать, а ключ в `config.js` — публичный anon-ключ Supabase (так задумано: права задаются политиками RLS в базе). С такими политиками любой, у кого есть ссылка, может добавлять и править карточки, но **не может физически удалить** их и не может трогать справочник OdanLab и журнал правок. Если понадобится вход по паролю/почте — это делается через Supabase Auth заменой политик `anon` на `authenticated`.

## Локальный запуск

```
python3 -m http.server 8000
```
и откройте http://localhost:8000. Без папки `ketcher/` редактор структур заменяется полем SMILES (всё остальное работает). Чтобы проверить Ketcher локально — скачайте `ketcher-standalone-*.zip` из [релизов](https://github.com/epam/ketcher/releases) и распакуйте в `ketcher/` (папка в `.gitignore`).
